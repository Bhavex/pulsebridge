Clear by design

Privacy policy.

PulseBridge helps people connect without turning a donor directory into a contact list. This plain-language summary explains what the site collects and who can see it.

Version 1.0 · Replace with your organization’s legal review date before launch.
01

What we collect

When you sign in, Google sign-in (through Supabase Authentication) provides your Google display name, email address, and user ID. When you send a contact request, PulseBridge stores your name, phone, short message, urgency, signed-in user ID, signed-in email, donor ID, request status, and creation time.

02

Donor information is separated

Public donor directory records contain only the donor name, age, blood group, city, state, availability, normalized search fields, and creation time. Phone and email are stored in a separate private table. Database security policies allow only PulseBridge admins to read it.

03

Consent is required

Donors must be at least 18 and must give consent before an admin can save a listing. Admins should collect that consent through their own approved process and keep it current. Receivers should share only what the admin needs to follow up.

04

Who can see what

Signed-in users can read the public donor directory. Signed-out visitors cannot read donor records or contact requests. Only accounts on the PulseBridge admin list can read private donor details and manage requests. Client-side checks improve the experience; database security policies are the actual security boundary.

05

Medical disclaimer

PulseBridge is not a hospital, blood bank, clinician, or emergency service. Compatibility, donation eligibility, urgency, and treatment must be confirmed by qualified medical professionals. If this is an emergency, contact local emergency services and medical providers immediately.

06

Retention and changes

The project owner should define retention periods, admin access reviews, and a process for donor removal before launch. Update this policy when the data flow changes, and keep the sign-in redirect settings and database security policies reviewed.
